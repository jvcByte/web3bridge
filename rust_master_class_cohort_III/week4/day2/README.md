### The honesty note: today's API cannot persist anything

`POST /posts` accepts a body, assigns an id, and echoes the created post back. `GET /posts`
returns a hardcoded seed list. **The post you just created does not appear in it.**

This is deliberate, and you should point it out in class rather than paper over it. A handler
is a plain `async fn` — it owns nothing that outlives the request. To keep a post you need
state that is shared across requests *and* across threads, which is exactly Day 3's
`Arc<Mutex<_>>`. Let the students feel the gap today so the fix means something tomorrow.

Ask them: where *could* you put the `Vec<Post>` so both handlers see it? Let them propose a
global `static mut`, then explain why the compiler refuses.

## Concept notes for the 11:00 block

**Why Axum instead of Actix.** This is on the end-of-phase interview question list, so answer
it properly. Axum is built directly on `hyper` and `tower`, which means its middleware is just
`tower::Service` — the same `Layer`/`Service` traits used across the whole Rust networking
ecosystem, and the thing you will implement by hand in Week 6 Day 4. It has no custom actor
runtime and no macro-based routing; a handler is an ordinary `async fn` and the router is an
ordinary value. It is maintained by the Tokio team, so it tracks Tokio's own releases. Actix
Web is fast and mature, but its middleware story is bespoke to Actix and historically leaned
on `unsafe` internally. We choose Axum because what you learn transfers.

**How a handler can be a plain function.** This is the piece of magic worth unpacking. Axum
has a blanket impl of its `Handler` trait for any async function whose arguments all implement
`FromRequestParts` (or, for the final one, `FromRequest`) and whose return type implements
`IntoResponse`. Nothing is registered; the type system does the wiring. Consequence: when you
get a wall of trait-bound errors on `.route(...)`, the real error is almost always "one of your
arguments isn't an extractor" or "your return type isn't `IntoResponse`". Teach them to read
the error that way.

**Extractor order matters.** `FromRequestParts` extractors (`Path`, `Query`, `State`,
`HeaderMap`) can be many and go anywhere. A `FromRequest` extractor (`Json`, `String`, `Bytes`)
consumes the body, so there can be only one and **it must be last**. Put `Json` before `Path`
and the compiler complains in a way that reads like nonsense until you know this rule.

**Serde is derive-driven, not reflection-driven.** `#[derive(Serialize)]` generates real code at
compile time — there is no runtime type inspection. Show `#[serde(rename_all = "camelCase")]`
and `#[serde(default)]` and let them see that the wire format is decoupled from the Rust names.

**Axum 0.8 path syntax.** Captures are `/posts/{id}`, not `/posts/:id`. The master curriculum
document was written with the older `:id` form; axum changed this in 0.8 to free up `:` and to
match the `{*wildcard}` syntax. If a student copies `:id` from a 2023 tutorial the route will
match the literal string `:id` and they will get a confusing 404 — flag this before the lab.
